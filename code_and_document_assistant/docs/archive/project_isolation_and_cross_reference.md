## 設計目標

每個專案都有獨立工作階段，預設只讀取與修改目前專案。需要參考其他專案時，由使用者明確加入，且參考專案只能唯讀，避免修 A 改到 B。

## 使用者選擇

- 目標專案：目前任務唯一可以修改的專案。
- 參考專案：使用者明確選取後加入，只能讀取與搜尋。
- 對話工作階段：切換回專案時恢復該專案自己的對話與任務紀錄；只有按「新對話」才另建。摘要不自動帶入其他專案。
- 登錄：同時支援前端與設定檔；設定檔登錄不自動授予寫入權限。
- 參考操作：介面選取與 `@project` 均支援；`@project-b` 只加入唯讀參考，修改 B 必須使用專案切換器。
- 每個檔案：顯示專案名稱、完整路徑、版本或 hash。

## A 與 C 的差異

兩者都可以要求 B 唯讀，但範圍不同：

- A：只說明「加入 B 為唯讀參考」，沒有明確規定預設專案邊界與參考清單管理方式。
- C：明確規定預設只能處理 A；只有使用者選取後才加入 B；B 永遠只能唯讀。

因此本專案採用 C，隔離規則較清楚，也較適合避免誤修改。

## 建議的任務資料模型

```text
工作階段
├─ targetProject: project-a
├─ referenceProjects: [project-b]
├─ allowedActions: [read, search, modify, verify]
└─ conversationSummary: 目前任務摘要
```

工具執行前必須檢查：

1. 目標檔案是否屬於 `targetProject`。
2. 參考檔案是否屬於 `referenceProjects`。
3. 參考專案是否為唯讀。
4. 檔案版本是否仍與提出差異時相同。
5. 修改或驗證權限是否在授權範圍內。

## 跨專案參考流程

```text
開啟專案 A
  → 提出需求
  → 明確加入專案 B 為參考
  → 搜尋 A 與 B
  → 產生只針對 A 的修改差異
  → 使用者確認
  → 寫入 A
```

從 B 引用程式或文件內容時，答案應保留：

- 來源專案
- 完整路徑
- 來源位置
- 版本或 hash
- 只能參考、未修改 B 的說明

## Codex 式多專案隔離

目前以穩定 root ID 作為 projectId，API 使用明確目標與參考範圍；索引記錄帶 rootId，查詢與手動更新按範圍過濾。各專案對話保存至磁碟。索引仍在同一 Workspace 物件內按專案分組，並非獨立資料庫或作業系統沙箱；服務的資料夾授權仍共用，不代表多使用者登入權限。

要達到真正隔離，建議改為：

```text
code_and_document_assistant/
├─ runtime/
│  ├─ assistant-state/    # 索引、工作階段、稽核
│  └─ test-runs/          # 測試與瀏覽器產物
├─ workspaces/
│  ├─ project-a/          # 實際專案 A
│  └─ project-b/          # 實際專案 B
├─ templates/             # 生成範本
└─ tests/                 # 自動測試
```

實際外部專案也可以註冊為工作區，不一定要搬入 `workspaces/`；重點是每個工作區必須有穩定的 `projectId`、根路徑、權限與索引範圍。

## 目前與未來功能邊界

- 授權指定資料夾：已有。
- 讀取與修改版本檢查：已有單檔流程。
- Select2 實際生成專案：已有固定 Mock 範本。
- 專案清單與目前專案：已接前端與設定檔，登錄資訊持久保存。
- 每個專案索引：同一儲存物件按 rootId 分組並限定讀取／更新，尚未拆獨立資料庫。
- 明確加入唯讀參考專案：已有勾選清單與 @project 選項。
- 跨專案搜尋但只修改目標專案：HTTP、讀取、提案、套用、還原與驗證均檢查範圍。
- 切換專案恢復各自對話：同一瀏覽器身分可重啟恢復歷史，舊提案不恢復執行能力。
- 測試產物與實際專案完全分離：仍需補強。

## 避免專案污染的必要規則

- 不把所有授權根目錄的檔案混成單一未分組清單。
- 每個索引項目必須帶有 `projectId`。
- 修改 API 必須同時接收並驗證 `targetProjectId`。
- 參考專案只能提供搜尋與讀取工具。
- 不允許模型自行把參考專案變成修改目標。
- 差異畫面顯示專案名稱與完整路徑。
- 外部修改造成 hash 不一致時拒絕套用。
- 對話摘要可以壓縮，但檔案與版本資料必須重新讀取確認。

## 版本保存與整案還原

本節是後續規格，尚未實作整案版本功能。

助手每次套用修改前，自動保存目標專案可還原版本。整案還原前再保存現況，使回到舊版後仍可找回新版。只保證已保存的版本；外部編輯器未被保存的中間變動不保證存在。

版本範圍包含程式與文件，排除 node_modules、暫存、密鑰與外部資料庫。保存結果必須列出納入／排除檔案；對話獨立保存，不隨程式還原倒退。整案還原需先預覽新增、修改與刪除，核對目前版本與授權，失敗時回報部分狀態；不得把現有單檔備份當成整案還原已完成。

## 成果收藏與測試歷史

本節是後續規格，尚未提供收藏介面或遷移舊測試。

使用者確認後才收藏成果快照，附用途、依賴、來源專案版本及實測／未測項目。後續收藏新增版本，不覆蓋舊收藏；可從收藏複製成新的獨立專案。收藏原件唯讀，測試成功不自動等於收藏。

實際專案放 workspaces/ 或已登錄的外部工作區；版本與收藏存於工作區之外的 assistant-state/versions/、assistant-state/collections/，避免再次被索引或納入自身快照。測試歷史放 runtime/test-runs/。

既有 runtime/select2-walkthrough-* 將標示為測試歷史並遷移；遷移前核對路徑與內容、建立原路徑對照，更新引用。已被使用者當作日常專案修改的實例需先辨識並保留其工作用途。本次尚未移動或刪除任何歷史檔案。

## 改版驗收標準

1. A 可修改，明確加入的 B 只能讀取，未加入 C 不出現在搜尋與引用中；HTTP 直接指定 B/C 也拒絕越界。
2. A/B 對話與任務獨立；切換、重新整理與服務重啟後按保存政策恢復，各分頁目標不互相改變。
3. 舊任務不能因前端切換而改變目標；修改／驗證仍綁定建立任務時的專案與權限。
4. 修改前版本可還原；還原前現況可找回；檔案增刪、外部修改、失敗及排除檔案均有測試。
5. 收藏保留歷版，可複製成獨立新專案；不包含密鑰與暫存。
6. 新測試在隔離區執行；歷史遷移有對照與完整性核對，成功成果不被自動清除。

實測與未完成項目摘要集中於 [../version_history.md](../version_history.md)；完整報告保留於 [test_report.md](test_report.md)，第一階段歷史基準見 [test_report_phase1.md](test_report_phase1.md)。

## 第二增量實際操作與保存規則

1. 重啟助手後，按「新增專案／管理授權」，在視窗內授權 A/B，或由 `CDA_PROJECTS_CONFIG` 預先登錄路徑（範例 `config/projects.example.json`）。設定檔不自動讀取或授權目標資料夾。
2. 點左側 A 的名稱切換目標。檔案清單顯示專案名稱、完整路徑及唯讀狀態。
3. 勾選 B 為唯讀參考，或輸入 `@project` 後點選選項。文字本身不授權；需透過選項加入實際 ID。B 不可套用修改或執行驗證。
4. 切換回 B 會恢復 B 的對話；可展開 B 下方清單重開舊對話，或按「新對話」。有草稿先提示，確認切換後才清除舊選取與編輯畫面；背景任務仍綁定原專案。
5. 目標與最後選取的對話 ID 保存於分頁 sessionStorage；不同分頁不共用目前目標。重啟後外部專案需重新授權，歷史對話仍可查看，舊修改提案只能當紀錄。

`runtime/assistant-state/state.json` 保存專案登錄、瀏覽器工作階段與各專案對話（含來源片段）。不保存管理碼，不應提交 Git 或當成參考文件授權。讀取身分依同一瀏覽器 HttpOnly cookie，有效期 30 天，每次載入 session 續期；清除 cookie、換主機網址或換瀏覽器不會自動找回原身分，未提供登入／帳號復原。每對話限 100 個任務，達限請新增對話；舊紀錄不會自動刪除，總對話上限 500。

模型仍為 Mock，只保存與重現對話，尚未把歷史送入真實模型進行多輪推理。已持久化的是歷史結果，並非重啟後恢復正在執行的程式。

重疊父子根目錄會被拒絕作為隔離範圍。Select2 固定生成器仍在目前目標根目錄內建立子資料夾，不會自動將它註冊為另一個獨立專案；要獨立操作既有生成成果，先撤銷父資料夾授權，再授權生成成果的專案資料夾。舊檔案不需搬動。

## 結論

本專案可以朝 Codex 式多專案模式發展。最重要的原則是：一個任務只能有一個可修改目標，其他專案必須由使用者明確加入並保持唯讀；對話可以遺失，但專案現況由檔案、索引、版本與稽核紀錄保存。
