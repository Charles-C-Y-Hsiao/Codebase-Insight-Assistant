# 雙層授權與專案資料流程

## 重點（2026-09-16）

- 全域參考根目錄（例如 `C:\Web_Practice\ReAct`）只提供唯讀搜尋，自動加入新任務。
- 個別專案（例如 `my_collapsible_tool`）仍要獨立授權；目前選定且授權可寫的專案才可修改。
- 各專案 `demo/` 預設納入搜尋。它是專案自己的測試素材；不自動建立，也不搬移舊範例。
- 助手本身、npm 依賴、版本庫、執行狀態、備份與機密設定皆排除。
- API key 不改變資料夾或權限。真實 AI 尚未串接；目前搜尋與人工修改可實際操作。

## 前端操作

1. 重啟服務，以 `http://127.0.0.1:4317/` 開啟本機頁面，取得本次終端管理碼。
2. 按專案區頂部＋。授權類型選「全域唯讀參考根目錄」，輸入 `C:\Web_Practice\ReAct`，填期限，提出請求後以管理碼確認。全域類型不能建立資料夾、授權寫入或執行驗證。
3. 全域授權成功後不切換目標。側欄「全域唯讀參考」與中央唯讀參考列可看到有效範圍。
4. 再用頂部＋，選「個別專案」，輸入 `C:\Web_Practice\ReAct\my_collapsible_tool`，按需要勾選修改與靜態驗證，完成主機確認並按「開啟此專案」。已有登錄可用該專案旁＋續期。
5. 按「更新文件索引」，更新範圍包含目標、明確加入的個別參考，以及有效全域參考。檔案清單、@file 與搜尋都會反映該範圍。
6. 選 A 的檔案即可進行人工修改提案與主機確認；B 的檔案只可讀取。要改 B，先獨立授權 B 並切換目標。

全域續期／撤銷在側欄「全域唯讀參考」操作。續期會帶入路徑與上次期限／AI 選項，仍需提出請求及主機確認。撤銷需要本分頁輸入的管理碼。授權到期會隱藏該來源檔案；重啟只保留登錄與預填，不恢復權限。

## 資料位置與範圍

```text
C:\Web_Practice\                 ← npm 集中位置；不在此次全域參考下
└─ ReAct\                        ← 全域唯讀授權
   ├─ my_collapsible_tool\       ← 選定後，可另授權寫入
   │  ├─ index.html
   │  └─ demo\                   ← 預設可搜尋的專案測試素材
   ├─ another_project\          ← 全域授權提供唯讀參考
   └─ code_and_document_assistant\ ← 排除於外部索引
      └─ runtime\demo\          ← 原有 Mock 展示工作區，仍獨立存在
```

目標專案內的 demo 檔案受相同專案授權管理：搜尋是唯讀操作；若要修改其中程式，仍需目標專案写入權限、提案與確認。其他專案的 demo 僅能唯讀參考。

同一路徑同時出現在目標與全域索引時，只顯示一次，優先目標，再個別參考，最後全域來源。全域來源不能作為修改目標，也不能通過提案／套用／驗證路由取得寫入能力。兩個一般專案彼此重疊仍拒絕；只有全域參考與子專案的雙層重疊被允許。

## 排除與索引限制

由 `src/path-policy.js` 統一排除助手實際安裝目錄與狀態目錄，以及 `code_and_document_assistant`、`node_modules`、`.git`、`.venv`、`runtime`、`backups`、`backup`、`assistant-state`、`.codex`、`.agents`；`.env*`、`.npmrc`、名稱含 secret／credential、PEM／KEY 與助手寫入暫存也排除。規則用於索引、授權及讀取檢查；符號連結不支援。

`demo/` 不在排除名單。npm 保持集中於 `C:\Web_Practice`；本次未移動或建立 npm 檔案，也未搬動既有使用者範例。舊 runtime 中的外部測試專案因位於排除範圍，需要自行複製所需成果至獨立正式專案後重新授權。

仍沿用檔案數量、總大小、深度與索引逾時上限；全域目錄過大會顯示未處理原因，不保證一次收錄所有資料。優先處理個別專案，再處理全域索引。外部修改或跨專案修改後請更新索引；舊版本讀取會拒絕並提示更新。

## 檔案與函式

- `server.js`
  - 入口：`roots/request`、`roots/:id/approve`、`catalog`
  - 責任：類型驗證、主機授權、登錄保存、分開提供專案與全域清單。
- `src/workspace.js`
  - 入口：`authorize`、`update`、`safePath`
  - 責任：全域強制唯讀、解析索引、期限與實體路徑檢查。
- `src/path-policy.js`
  - 責任：共用排除與路徑範圍規則。
- `src/project-scope.js`
  - 入口：`constructor`、`files`、`check`
  - 責任：保存任務參考 ID、去重與目標寫入限制。
- `public/app.js`
  - 入口：`setRootKind`、`catalog`、`renderGlobalReferences`
  - 責任：授權選擇、全域狀態、續期與撤銷。
- `public/sidebar.js`
  - 入口：`allGrantRoots`、`scheduleExpiry`
  - 責任：兩層授權倒數與到期隱藏。

## 真實 AI 邊界

授權允許本機搜尋不等於 AI 外送同意。real adapter 已實作，`permissions.ai` 現在用於逐來源外送檢查及每輪重驗；全域許可不可繞過更具體子專案的禁止。需要設定 endpoint、模型、認證並實測後使用，見 [AI 連線流程](../ai_connection_flow.md)。本次只使用假 key／假模型驗收。
