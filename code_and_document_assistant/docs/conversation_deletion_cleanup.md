# 一般專案對話刪除與 Runtime 清理

## 刪除單張任務卡片

一般任務卡片右上角提供 Delete，確認後刪除該卡片及所有需求版本。已寫入的一般專案檔案、備份和共用稽核紀錄保留；一般生圖的專案內 PNG、JSON 與任務歸檔亦保留，可由歸檔還原。圖片創作專案任務受保護，不可由此功能刪除。

刪除會移除來源為該任務及其版本的已確認需求，並依剩餘取代關係恢復先前需求；本機摘要依剩餘任務重建。結構化摘要及其更新紀錄保留有明確來源且未涉及被刪任務的項目，移除受影響或來源不明項目，並標示刪改；下次整理時重建。模型產生的來源 ID 可能漏標，不能保證保留項目完全不含已刪內容。歷史篩選快照保留可辨識的其他候選任務，移除被刪任務及來源不明的固定內容、摘要與篩選理由，並標示不再是完整原始快照。後續任務的需求與回答原文保留，故原文中間接提到的內容仍可能再次進入歷史。

執行中的目標任務會取消；正在寫入的動作等待完成。若同一對話的其他任務或記憶整理仍在執行，或等待超過 30 秒，保留卡片並提示重試。一般生圖的專案歸檔不完整時也會阻止刪除；中央圖片清理僅針對該任務對應的 PNG／JSON，不刪除共用系列資料夾。

## 目標

刪除一般專案對話時，移除對話索引及只屬於該對話的 Runtime 資料；一般生圖的 PNG、JSON 與完整任務紀錄保存在專案自己的隱藏歸檔中，刪除對話不會刪掉它們。

## 清理範圍

- `runtime/assistant-state/state.json`
  - 移除該使用者、一般專案與對話 ID 對應的對話、任務、結果和摘要。
- `runtime/assistant-state/generated-images/<專案 ID>/<對話 ID>/`
  - 移除該對話尚未搬移的舊版一般生圖 PNG 與 JSON。
  - 圖片專案任務仍使用此中央區域，但含有這些任務的對話會被阻止刪除。
- 一般專案的 `.cda/image-generations/<使用者 ID>/<對話 ID>/<系列 ID>/`
  - 保存一般生圖 PNG、圖片 metadata JSON 與 `<任務 ID>.task.json` 完整任務紀錄。
  - 任務紀錄保留提示詞、結果、狀態、版本、來源圖片與所屬對話 ID，可經歸檔 API 還原回 `state.json`。
- 服務記憶體中的附件草稿
  - 清除該對話的圖片草稿；這些草稿不寫入一般專案資料夾。
- `runtime/assistant-state/generated-images/` 中已無任何 `state.json` 對話索引的對話目錄
  - 盤點後清除孤立目錄。
  - 若對應的任務仍在執行，暫時保留該目錄。

## 圖片創作專案任務的保護

圖片專案任務會跨一般對話與圖片專案資料夾保存，目前仍有部分索引掛在一般對話上，不能隨一般對話一併刪除：

- `runtime/assistant-state/state.json`
  - `imageProjects` 保存圖片專案與系列中繼資料、摘要與摘要版本。
  - `conversations[].jobs` 保存圖片討論與圖片創作任務本體；任務透過 `imageProjectChat.projectId/seriesId` 或 `imageCreation.imageProject.id/seriesId` 關聯圖片專案。
- `runtime/assistant-state/generated-images/<一般專案 ID>/<對話 ID>/<系列 ID>/`
  - 保存圖片創作版本 PNG 與 JSON。
- `../image-creation/<圖片專案資料夾>/`
  - 保存圖片專案的附件、參考圖，以及 PNG 與 JSON 輸出副本。

因此，若對話中存在圖片專案任務，`DELETE /api/conversations/:id` 會拒絕刪除並保留所有索引與檔案。這是保護措施；目前尚未把任務索引遷移到圖片專案自己的持久化儲存，因此這類對話不能透過一般對話刪除流程移除。一般專案資料夾內容也不會因這項保護而移動或修改。

## 保留範圍

- 一般專案資料夾中的檔案，包括已套用的 AI 修改和建立檔案。
- `.cda/image-generations/` 中的一般生圖產物與完整任務紀錄；這是專案內的助手歸檔子目錄，會從一般檔案索引排除。
- `runtime/backups/` 中的專案檔案備份。這些備份可用於還原仍存在於專案資料夾的檔案。
- 共用的 `runtime/audit.jsonl`。它包含授權、修改與刪除紀錄，目前沒有對話 ID 關聯。
- 驗證規則、專案授權資料及其他共用設定。

## 刪除前置條件與邊界

- 若對話含有圖片創作專案的討論或創作任務，刪除 API 回覆 HTTP 409，整筆保留對話、任務索引與檔案；不開始取消或清理流程。
- 一般生圖需要 AI 外送權限與目前專案的「允許修改」權限，才能把產物寫到專案歸檔。
- 舊的一般生圖中央檔案會在下一次一般生圖或刪除對話時搬移：先複製 PNG／JSON 和任務紀錄至專案歸檔、驗證副本並保存全域索引，再移除中央副本。
- 若刪除時仍有未完整歸檔的圖片或任務紀錄，且目前沒有有效的專案寫入權限，API 回覆 HTTP 409，保留對話及來源檔案，要求重新授權後重試。
- 其他一般對話只有在送出中的操作已結束、執行中任務已取消、檔案寫入已完成後，才會清除其 Runtime 記錄。
- 刪除一般對話不會刪除一般專案資料夾中的一般檔案或 `.cda/image-generations/` 歸檔；已確認的專案寫入照常保留。
- `runtime/backups/`、共用 `runtime/audit.jsonl` 與設定不屬於單一對話的清理範圍。
- 若取消、請求排空或檔案寫入超過 30 秒，保留對話索引及其 Runtime 資料，回報稍後重試。

## 執行中任務與競態處理

- 對話刪除開始後，阻止該對話送出新的變更操作。
- 取消執行中的一般 AI 任務與圖片創作任務，並等待其完成取消與保存程序。
- 對正在套用或建立檔案的任務等待寫入完成；完成後保留專案檔案，再清除 Runtime 對話資料。
- 若送出中的請求、取消或寫入在 30 秒內仍未停止，停止等待並保留對話與其 Runtime 資料，提示使用者稍後重試。
- 只有任務都停止後，才清除對話生圖目錄並移除 `state.json` 對話索引。
- `state.json` 保存失敗時，在記憶體中還原對話項目，讓使用者可以重試。
- 刪除完成後寫入共用稽核紀錄；若稽核寫入失敗，回報警告，不復原已完成的刪除。

## 驗收條件

- 刪除完成後，`state.json` 中找不到該對話。
- 該對話 ID 對應的中央生圖目錄不存在。
- 可確認孤立的對話生圖目錄已清除。
- 一般專案資料夾、共用備份和稽核紀錄保持可用。
- 任務停止逾時時，對話索引和 Runtime 檔案均保留，重試仍可完成清理。
- 含圖片專案討論或創作任務的對話，刪除請求會被拒絕，原對話、圖片任務索引與圖片專案檔案均保留。
- 一般對話刪除不更動一般專案資料夾、共用備份、稽核紀錄或設定。
- 刪除一般對話會移除 `state.json` 的即時對話索引，但專案歸檔 API 仍能列出並還原一般生圖任務。

## 專案生圖歸檔與還原

- `GET /api/project-image-archive`：列出目前一般專案中屬於目前使用者的一般生圖歸檔。
- `POST /api/project-image-archive/:jobId/restore`：從專案歸檔還原單筆任務及原對話索引至 `state.json`。
- 全域 `state.json` 仍是目前工作介面的索引；專案 `.task.json` 是刪除對話後可用來還原的持久任務紀錄。

## 後續補強

- 將圖片討論與創作任務索引遷移至圖片專案／系列自己的持久化資料，讓其生命週期不再依賴一般對話索引。
- 遷移完成並驗證任務、版本、附件、參考圖與摘要來源可從圖片專案完整讀取後，再允許刪除承載過這些任務的一般對話。
- 目前工作目錄沒有 `runtime/assistant-state/state.json`，因此不能從此 checkout 列舉執行環境中的具體對話 ID；本節記錄的是由資料結構與路徑確認的保存關係。
