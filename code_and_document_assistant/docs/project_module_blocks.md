# 專案模組化區塊規劃

本文件是整個專案的功能分類索引；網頁「目前專案的 Harness 功能」從工具與執行控制的角度整理已實作能力。兩者為多對多關係，內容目前由人工維護，沒有自動同步。

- **一般專案管理**
  - 專案登錄、切換、目錄與檔案索引。

- **圖片專案與系列管理**
  - 圖片專案、系列切換、命名與版本關係。

- **對話與任務執行**
  - 對話歷史、任務狀態、取消與執行追蹤。

- **服務啟動與 API 驗證**
  - 掃描單一 Node 入口與預期 Port，確認後啟動受追蹤的服務程序。
  - 保存專案外 `node_modules` 路徑；提出外部依賴安裝計畫並等待確認。
  - 啟動時驗證程序及 `127.0.0.1` Port，之後每 30 秒檢查一次，最多五分鐘；保留初始監測、錯誤及截斷輸出，提供服務停止功能。
  - 設定 API 方法、路徑、標頭、Body、預期狀態及回應條件；可掃描最近修改影響的 Express 路由，確認後驗證並保存遮罩結果。
  - 主要實作：`src/project-services.js`、`public/project-services-ui.js` 與 `server.js`。

- **AI 請求與上下文**
  - 模型設定、材料組裝、歷史篩選與逾時處理。
  - [對話模型選擇](text_model_selection.md)：模型 ID／顯示名稱／啟用清單、思考深度、逐對話保存與逐操作快照。

- **圖片討論與創作**
  - 圖片理解、候選提示詞、產圖與修改流程。

- **摘要與記憶管理**
  - 對話、專案及系列摘要的產生與套用。

- **附件與檔案保存**
  - 附件、圖片、JSON 與任務索引的保存。
  - 三種保存模式：[storage_models.md](storage_models.md)

- **資料刪除與完整性**
  - 任務卡、整個對話、一般專案、圖片系列與整個圖片專案的刪除邊界與確認流程。
  - 刪除一般專案時，先完成必要的圖片與任務封存，再清理登錄、所有工作階段的對話及相關索引；保留磁碟專案資料夾與檔案。
  - 刪除整個圖片專案時，先將清單、任務、摘要與提示詞整合紀錄保存至 `.cda/deletion-archive/`，再清理所有工作階段的相關任務與索引；保留原圖片資料夾、產出檔案與其他專案的獨立複製品。
  - 清理受影響的確認需求、記憶來源、歷史快照及版本引用，並標記已移除來源；盤點執行中操作與跨專案依賴，封存失敗時阻止整個專案刪除。
  - 孤立檔盤點與中斷復原。單一圖片系列的刪除目前仍只清理提出刪除的工作階段，與整個圖片專案的清理範圍不同。
  - 一般對話：[conversation_deletion_cleanup.md](conversation_deletion_cleanup.md)
  - 圖片系列：[image_project_deletion_cleanup.md](image_project_deletion_cleanup.md)
  - 整個圖片專案：`src/image-project-deletion.js`；一般專案與各刪除 API：`server.js`。

- **授權與存取控制**
  - 磁碟授權、AI 外送同意與管理碼驗證。

- **前端介面與互動**
  - 工作區、選單、對話框與操作狀態呈現。
