# 圖片創作系列永久刪除與資料清理補強紀錄

## 目的

圖片創作專案的「永久刪除系列」必須刪除該系列的任務紀錄與所有只屬於該系列的檔案，避免 `state.json` 已無索引、磁碟卻仍殘留圖片或附件。

本文件只涵蓋圖片創作專案的系列刪除。一般專案對話的清理範圍與流程記錄於 [conversation_deletion_cleanup.md](conversation_deletion_cleanup.md)。

## 資料位置與索引關係

系列資料分散在下列位置：

- `runtime/assistant-state/state.json`
  - `imageProjects`：專案、系列名稱與摘要。
  - `conversations[].jobs`：圖片討論與圖片創作任務。
  - 圖片討論以 `imageProjectChat.projectId`、`seriesId` 關聯系列。
  - 圖片創作以 `imageCreation.imageProject.id`、`seriesId` 關聯系列。

- `runtime/assistant-state/generated-images/<一般專案 ID>/<對話 ID>/<系列 ID>/`
  - 圖片創作產出的 PNG 與 JSON 版本檔。

- `../image-creation/<圖片專案資料夾>/`
  - 圖片討論送出的持久化附件。
  - 圖片創作送出的持久化參考圖片。
  - 圖片專案輸出的 PNG 與 JSON 副本。

一般對話的直接生圖另存於所選一般專案的 `.cda/image-generations/`，並不屬於圖片專案系列資產；系列永久刪除不會清理該歸檔。兩種流程的保存與對話刪除規則不同，詳見[一般對話刪除紀錄](conversation_deletion_cleanup.md)。

同一張參考圖可能同時出現在圖片討論附件與圖片創作的 `imageCreation.references`。刪除時應以檔名去重後刪除；重複刪除必須可安全執行。

一般對話刪除對圖片專案任務的保護與目前索引依賴，另見 [conversation_deletion_cleanup.md](conversation_deletion_cleanup.md)。圖片專案任務索引尚未完全獨立於一般對話，因此含有這些任務的對話會被一般對話刪除流程阻止。

## 已發現的問題

2026-10-16 的索引盤點發現：

- 中央 `generated-images` 的 24 個 PNG／JSON 都有 `state.json` 任務索引。
- 圖片專案資料夾曾有 1 個未索引附件：
  - 專案：`cf2c0652d61`
  - 系列：`圖片創作mermaid`
  - 檔案：`e9687eab-0c9a-433b-854f-c6b12516e710-attachment-39a13d27-a4cd-4d2a-b912-0140043c4626.jpg`
- 該檔案不在任何圖片討論附件、圖片創作參考圖或輸出版本的紀錄中；已經人工確認並安全移除。
- 移除後，三個圖片創作專案皆為「未索引檔案 0、索引檔案缺失 0」。

根因是舊版永久刪除流程只清除 `job.attachments`，未清除 `job.imageCreation.references` 中的持久化參考檔。當系列被永久刪除時，這類檔案可能成為孤立資料。

## 目前已修正的永久刪除行為

`DELETE /api/image-projects/:id/series/:seriesId` 現在會：

- 拒絕刪除仍有執行中任務的系列。
- 找出該使用者、該圖片專案、該系列的圖片討論與圖片創作任務。
- 刪除任務的 `attachments` 持久化附件。
- 刪除任務的 `imageCreation.references` 持久化參考附件。
- 刪除中央版本保存區的 PNG 與 JSON。
- 刪除圖片專案資料夾中的 PNG 與 JSON 副本。
- 從對話任務、執行中的任務集合、`imageProjects` 系列清單移除該系列資料。
- 移除中央版本保存區的整個系列資料夾。
- 寫入 `delete-image-series` 稽核紀錄，並保存 `state.json`。

## 刪除邊界與共用資料保留

- 系列永久刪除只清理該圖片系列的任務索引、附件、參考圖、PNG／JSON 及該系列的摘要中繼資料。
- 一般專案資料夾中的檔案不屬於系列資產，不會被系列刪除流程修改。
- `runtime/backups/`、共用 `runtime/audit.jsonl`、驗證規則、專案授權資料及其他共用設定均保留；刪除動作會新增稽核事件，不會清空共用稽核檔。
- 若系列仍有執行中的任務，系列刪除會先拒絕，不清除索引或檔案。一般對話含圖片專案任務時則由一般對話刪除流程回覆 HTTP 409，詳見[一般對話刪除紀錄](conversation_deletion_cleanup.md)。

已由 `tests/image-project-flow.test.js` 驗證：包含創作參考圖的系列在永久刪除後，來源專案資料夾會清空，而匯入到另一專案的副本仍會保留。

## 後續補強項目

- 建立可重複執行的「圖片專案儲存盤點」工具。
  - 列出每個檔案的索引來源：討論附件、創作參考圖、產出 PNG 或 JSON。
  - 分別輸出未索引檔案與索引存在但檔案缺失的項目。
  - 預設只讀；實際清除需明確指定檔案或採用確認機制。

- 將刪除目標先整理為唯一檔名集合，再執行檔案刪除。
  - 讓同一檔案被附件與參考圖同時引用時只刪除一次。
  - 在回應與稽核紀錄中保留刪除的任務數、圖片數、附件數與檔案數。

- 將刪除流程拆成可觀察的階段。
  - 建立刪除清單。
  - 刪除檔案。
  - 更新記憶體中的任務與系列資料。
  - 保存 `state.json`。
  - 完成後再次盤點該系列目錄，若仍有檔案則回報失敗而非宣告完成。

- 增加中斷復原策略。
  - 若服務在檔案刪除與 `state.json` 保存之間停止，下次啟動時應能辨識未完成的刪除交易。
  - 可採用刪除工作紀錄或暫存 tombstone；恢復時繼續清理或提供明確的修復提示。

- 在圖片附件第一次寫入專案資料夾後，保證它會被任務引用或被立即清除。
  - 對授權拒絕、格式錯誤、模型能力不符、請求中斷等建立任務前失敗情境，都要留下可追溯原因並移除附件草稿檔。

- 將一般專案對話的刪除流程納入獨立盤點。
  - 不應假設一般對話刪除與圖片系列永久刪除具有相同的檔案清理保證。

## 驗收條件

完成補強後，永久刪除一個圖片系列應符合：

- `state.json` 中不存在該系列的 `imageProjectChat` 或 `imageCreation` 任務。
- 中央 `generated-images` 中不存在該系列目錄。
- 圖片專案資料夾不存在該系列的附件、參考圖、PNG 或 JSON。
- 刪除不會影響已匯入其他圖片專案的副本。
- 稽核紀錄能說明刪除範圍與結果。
- 盤點工具對刪除後的系列回報未索引檔案 0、缺失索引檔案 0。
